## Non-blocking findings

### N1 — New v3 selection-only records are serialized under the legacy label
- **Severity:** Low (provenance/auditability; no current consumer is misled)
- **Path/line:** `npa/src/npa/orchestration/npa_workflow/runtime.py:320-327`, producer at `:2259-2260`
- **Trigger:** A wave whose `plan_images` yields no image at all (every step is `run:`-only with no `resources.image`, no catalog tool, and no `*` override). Then `references == ()`, so `attempt.image_digest = _image_identity(self.render_options)` — the **v3 selection hash** — while `image_identity_version` stays `""`.
- **Consequence:** `_image_identity_record` emits `{"version": "", "kind": "legacy_digest_pin_set", "legacy_digest_pin_set_sha256": <v3 selection hash>}`. A ledger reader or future migration that keys off `kind` will treat a v3 selection hash as an old pin-set hash. This is the exact "cannot silently relabel old hashes" property the change set claims. Current readers are safe because `_expected_image_identity` branches on `version`/`references`, not `kind`.
- **Evidence:** `runtime.py:322-327` is the only `version == ""` serialization branch; `runtime.py:2259-2260` is the only writer that reaches it, and it now writes v3 material. The test at `npa/tests/orchestration/npa_workflow/test_runtime_orchestrator.py:135-139` locks in `legacy["kind"] == "legacy_digest_pin_set"` for exactly this shape.
- **Smallest remedy:** In `_image_identity_record`, distinguish the two producers — e.g. emit `{"version": "", "kind": "selection_only", "selection_sha256": attempt.image_digest}` when `attempt.image_selection_sha256 == attempt.image_digest`, and keep `legacy_digest_pin_set` only for restored records. Update the test at `test_runtime_orchestrator.py:138`.

### N2 — Wave identity is invalidated by digest-pin changes to images that wave never used
- **Severity:** Medium operability (fail-closed; no correctness or duplication risk). Deliberate per docs and tests — flagged because the cost is asymmetric.
- **Path/line:** `npa/src/npa/orchestration/npa_workflow/runtime.py:225-249` (hashes the whole `image_digest_pins`/`image_overrides` map) feeding `:2256-2258` and `:412-423`
- **Trigger:** A run with waves W1 (image A) and W2 (image B). W1 completes. On `--resume`, `_preflight_submit_images` (`cli/.../__init__.py:4464-4468`) re-resolves the **workflow-wide** pin map; image B's floating tag now resolves to a different digest.
- **Consequence:** `_image_identity` changes → `_selection_reference_identity(selection, refs_of_W1, bindings_of_W1)` changes → `_completed_replay_identity_mismatches` returns `["image_digest"]` → `_run_wave` raises `IMMUTABLE_IDENTITY_MISMATCH` for W1 even though W1's own resolved reference is byte-identical. The operator cannot resume; the documented remedy is a new run ID, which re-runs W1's already-completed GPU work.
- **Evidence:** `_preflight_submit_images` returns one map for the entire plan (`_plan_preflight_image_requirements` at `:4423-4428`), passed once into the executor's `render_options`. `test_image_identity_binds_digest_pins_to_reference_keys` parametrizes `"add"`/`"remove"` of an unrelated `cr.example/tool-c` pin and asserts `actual != expected`, so the behaviour is intentional and locked in. `docs/run-lifecycle.md` states "reassigning the same references or digest values changes identity."
- **Smallest remedy (if the cost is judged too high):** In `_selection_reference_identity`, hash a wave-scoped projection of the selection instead of the global hash — i.e. pass `_image_identity` a `SkypilotRenderOptions` filtered to the pins whose key or value appears in this wave's `references`, and to the selectors that matched this wave's tool refs. Global `registry`/`gpu_target`/`image_variant` stay whole. Otherwise: no change; this is a stated design choice.

### N3 — `reconcile_output_reuse_decision` fence is only applied on `outcome == "found"`
- **Severity:** Low (not reachable on the production path)
- **Path/line:** `npa/src/npa/orchestration/npa_workflow/runtime.py:1767-1774` (fence) vs `:1871` (`automatic_retry`)
- **Trigger:** An attempt carrying a validated durable reuse decision whose exact provider job reconciles as `absent`, **and** `attempt.launch_sequence == 0`.
- **Consequence:** `automatic_retry = attempt.launch_sequence == 0 or (...)` is True → `self.attempts.pop(); return None` (`:1993-1994`) → `_run_wave` submits a replacement job, discarding the durable decision that said the declared outputs were already valid.
- **Evidence:** `launch_sequence` is only advanced by the default SDK launch transaction (`skypilot/launch_transaction.py:842`), applied via `_apply_launch_transaction` (`runtime.py:2864`). In production `SkyPilotWaveExecutor` is constructed without a custom `submitter` (`runtime.py:3442` is the sole construction site), so a record with a `job_id` always has `launch_sequence > 0`, and the branch is unreachable. `test_decision_only_crash_never_relaunches_without_exact_provider_evidence` covers `absent` only with `launch_sequence > 0`. `explicit_retry` correctly excludes `reconcile_output_reuse_decision` from its allow-list (`:1916-1924`).
- **Smallest remedy:** Add `and attempt.recovery_decision != "reconcile_output_reuse_decision"` to the `automatic_retry` expression at `runtime.py:1871`, or hoist the fence above the `if outcome == "found":` branch so it also guards `absent`.

### N4 — `except NpaWorkflowError` in the replay gate misses plain `ValueError` from the image catalog
- **Severity:** Low (fail-closed; error-message contract only)
- **Path/line:** `npa/src/npa/orchestration/npa_workflow/runtime.py:2130`
- **Trigger:** A completed-wave replay where `resolve_task_image` routes to `container_image_for_tool` for a publication-quarantined tool without a tag.
- **Consequence:** `container_image_for_tool` raises a bare `ValueError` (`npa/src/npa/deploy/images.py:2358`, `:2368`, `:2375`). `NpaWorkflowError` subclasses `ValueError` (`errors.py:4`), but `except NpaWorkflowError` does not catch a plain `ValueError`, so it escapes `_completed_replay_identity_mismatches` and aborts `_run_wave` with a raw registry message instead of the canonical `IMMUTABLE_IDENTITY_MISMATCH (image_digest)` promised by item 4. No submission occurs.
- **Smallest remedy:** Broaden to `except (NpaWorkflowError, ValueError):` at `runtime.py:2130`.

### N5 — `_expected_image_identity` contains a dead empty-identity branch
- **Severity:** Low (dead code)
- **Path/line:** `npa/src/npa/orchestration/npa_workflow/runtime.py:412-414`
- **Evidence:** `_image_identity` (`:236-249`) always returns a 64-char `hexdigest()`; `if not selection: return ""` can never fire. It implies a supported "empty image identity" state that `_completed_replay_identity_mismatches` (`:2136`) would treat as a mismatch anyway.
- **Smallest remedy:** Delete lines 412-414.

### N6 — A mixed cancellation history for one logical attempt blocks, and is untested
- **Severity:** Low (fail-closed)
- **Path/line:** `npa/src/npa/orchestration/npa_workflow/runtime.py:1512-1515`
- **Trigger:** One logical attempt whose history contains both a non-reuse `cancellation` event (e.g. from the `relaunch_allowed` branch at `supervisor.py:711-717`) and a later reuse `cancellation` event.
- **Consequence:** Once `reuse_claimed` is true, the loop requires **every** cancellation event to pass `_output_reuse_terminal_status`, so the earlier non-reuse cancellation raises and the wave is blocked. Fail-closed, but it is a false block if that history is legitimately reachable. `test_resume_skips_well_formed_nonreuse_cancellation_event` only covers the single-non-reuse case.
- **Smallest remedy:** Either add a test asserting the mixed history is intentionally ambiguous, or filter `cancellations` to `recovery.action == "reuse_completed_wave"` before the per-event validation loop while keeping the existing ambiguity comparison.

### N7 — Minor / cosmetic
- `_render_docs` (`skypilot_render.py:2732-2746`) now materializes all task docs before the parallel duplicate-name check, so a later step's render error surfaces ahead of an earlier duplicate-name error. Behaviour-neutral for valid specs.
- Two broad `except Exception` handlers in `_resume_durable_output_reuse` (`runtime.py:1439`, `:1451`) are MEDIUM by `skills/atomic/review-checklist/SKILL.md`. Here they are the deliberate fail-closed seam and they do retain `type(exc).__name__` and a sanitized reason, so the traceback context is not fully discarded — noting for the record only.
- Transient-history behaviour change: `_resume_durable_output_reuse` runs *before* `_reconcile_exact` for **every** in-flight wave (`runtime.py:1761`), so a transient object-store LIST/GET failure on `npa-workflow/supervisor/attempts/<id>/` now aborts the resume and leaves a live provider job unmonitored, where the base reconciled and attached to it. This is intentional (`test_transient_history_failure_recovers_ordinary_live_attempt`) and documented in `docs/run-lifecycle.md`. Worth an operator-facing note that the remedy is re-resume after restoring access, not cancellation.
- No test exercises the empty-`references` producer branch (`runtime.py:2259-2260`) end-to-end through a successful replay; every fixture supplies either `image_overrides={"*": ...}` or `resources.image: tool://...`. This is the same branch as N1.
