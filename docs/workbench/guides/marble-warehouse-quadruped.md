# Walk a detailed Go1 through a Marble warehouse

[marble-warehouse-quadruped.yaml](../../../workflows/testing/marble-warehouse-quadruped.yaml)
reuses a warehouse generated by the World Labs API and records a simulated
Unitree Go1 inspection walk. One Nebius RTX PRO 6000 produces the camera images,
depth, and detailed observer render. Workbench submits both collection and
report stages through its normal SkyPilot runtime with S3 artifacts.

| Component | Execution | Output |
| --- | --- | --- |
| Official Go1 URDF and Google locomotion checkpoint | CPU PyBullet torque dynamics and ONNX inference | Measured body/link poses, twelve joint states, actions and foot forces |
| Marble Gaussian splats | gsplat CUDA | Onboard and observer warehouse RGB |
| Original Marble collision mesh | NVIDIA Warp CUDA | Onboard ray-distance depth |
| Detailed Go1 visual meshes and original warehouse shadow catcher | Blender Cycles CUDA GPU | Articulated robot with materials, occlusion and shadows |
| OpenImageDenoise | CPU | Denoised path-traced robot images |
| Verified collection bundle | CPU encoding and reporting | One offline HTML with three synchronized videos and telemetry |

This uses a pretrained walking policy. It does not train a new policy or connect
to a physical robot. The simulated walk follows a measured supported aisle in
the original concave collider. Collection fails if the robot falls, moves less
than one meter, or lacks foot contact in at least 80% of recorded observations.

## Run headlessly

First obtain a generated-world bundle using the
[Marble acquisition workflow](marble-to-nebius.md). Generation requires a funded
**`WLT_API_KEY`**, read from the operator environment or private NPA credentials.
Do not put it in YAML or HTML. Reusing the resulting `world.json`, SPZ and GLB
requires storage access, not another World Labs request or token.

Use a Linux operator with the configured project, exact Kubernetes context,
owned S3 destination, and pinned SkyPilot environment. Replace these placeholders:

```bash
npa workbench health preflight --project <project-alias> --checks nebius,s3 --json
npa skypilot verify --cluster <exact-context> --output-format json
npa workbench workflow validate-spec workflows/testing/marble-warehouse-quadruped.yaml
npa workbench workflow submit workflows/testing/marble-warehouse-quadruped.yaml \
  --project <project-alias> --infra k8s/<exact-context> \
  --run-id warehouse-go1-collection \
  --var bucket=<owned-bucket> \
  --var world_uri=s3://<owned-bucket>/<existing-world-prefix> \
  --stage-src --runtime --max-wait-seconds 0 \
  --secret-env AWS_ACCESS_KEY_ID --secret-env AWS_SECRET_ACCESS_KEY \
  --isolated-config-dir /var/lib/npa/warehouse-go1-sky
```

Pass `world_uri` without a trailing slash. Keep the isolated directory and Linux
operator for status, resume and cleanup. After an interrupted runtime, use
`--resume-run warehouse-go1-collection` with the same submission settings.
For a terminal failed or cancelled attempt, fix the reported cause and add
`--retries <count>`; the default preserves a terminal result without rerunning it.
Check `npa workbench workflow status warehouse-go1-collection --project
<project-alias> --json` before retrying. Follow the
[owned workflow cleanup procedure](../../teardown.md#owned-local-workflow-api)
after downloading the finished report.

Defaults are 500 observations at 25 Hz, 1280 × 720 pixels, 0.35 m/s commanded
forward speed, and 32 Cycles samples per pixel. Override through `--var frames`,
`width`, `height`, `sensor_hz`, `speed_mps`, or `samples`. The sensor frequency
must divide the 250 Hz physics clock. Policy control runs at 50 Hz after a
two-second settling period. Recorded positions and speed reflect actual
simulation, not the requested command.

The CLI is `npa workbench marble quadruped-collect --input-path <world-uri>
--output-path <collection-uri> --run-id <run-id>`. The SDK exports
`QuadrupedRequest` and `quadruped_collect` from `npa.sdk.workbench.marble`.
The workflow uses `workbench.marble.quadruped_collect`; all three invoke the
same stateless implementation. GPU work stays in the worker, not the agent
control plane.

## Inspect and reproduce

Download `runs/<run-id>/marble-quadruped/report/index.html` and open it directly.
The observer, onboard RGB and depth videos are embedded with the measured route,
joint positions, foot forces, source hashes and license notices. The file makes
no network requests and does not rerun the cloud workload during playback.

Live validation completed the native collection and report stages on one
RTX PRO 6000 Blackwell Server Edition: 500 observations at 1280 × 720 and 25 Hz,
a 6.06-meter simulated walk, and foot contact in all 500 observations. The
standalone HTML passed desktop and mobile playback, synchronized seeking, and
telemetry-download checks offline with zero network requests or JavaScript
errors. This validates the collection workflow, not new policy training.

The `results/` prefix preserves `trajectory.json`, raw `depth.npz`, JPEG camera
frames, the portable `go1.urdf`, pinned upstream assets, `actor-render.json`,
renderer logs/settings, and the hash manifest `result.json` with physics metrics.
CUDA event intervals and Cycles wall times measure different scopes; neither is
an active-GPU-time claim. The first CUDA call can include kernel compilation.
Cycles requires a detected CUDA device and disables CPU rendering fallback.
OpenImageDenoise runs on CPU and is recorded separately in renderer evidence.
Two Blender processes render disjoint frame batches on the same GPU, each with
four CPU threads. The collector checks complete, ordered batch evidence before
publishing. AgX tone mapping preserves detail in bright robot materials.

The asset manifest pins every upstream revision and SHA-256. Unitree meshes and
URDF use BSD-3-Clause; the Google MuJoCo Playground checkpoint uses Apache-2.0.
Their license texts accompany the downloaded assets and HTML. The portable URDF
removes the massless ROS root frame and gives missing optical frames zero mass,
preserving the dynamic trunk and original joint inertias. Blender is fetched
from its official release with a pinned archive hash; binaries are not baked
into the workbench image or included in the HTML.

Lighting and metal/rubber materials are authored for the observer. Warehouse
appearance comes from the original splats, while shadows and collision use the
approximate generated mesh. Provider-estimated scale is not site calibration.
This is useful for testing camera ingestion, mapping, trajectory alignment and
action/state recording. It does not establish manufacturing accuracy,
collision safety or transfer to a real robot. The separate
[navigation workflow](marble-navigation-rl.md) targets new GPU policy training;
its GPU training and held-out evaluation still require live qualification with
an operator-qualified Isaac image.
