# Train navigation in a Marble warehouse

[marble-navigation-rl.yaml](../../../workflows/testing/marble-navigation-rl.yaml)
consumes a world already generated by World Labs. It converts the original GLB
collider into a static Isaac scene, prepares supported reset cases, trains an
ANYmal-C navigation policy with native RSL-RL PPO, and evaluates the reloaded
checkpoint on separate goal locations.

The GPU work is **physics simulation, policy inference, and gradient updates**.
The policy observes geometric range scans and goal state. Gaussian splats are
not the training representation, and the workflow does not render camera data.
The upstream locomotion controller remains fixed; PPO learns navigation commands.

## Execution boundary

| Operation | Execution | Output |
| --- | --- | --- |
| Generate a warehouse | World Labs hosted API | Hash-verified SPZ/GLB world bundle in S3 |
| Prepare navigation | CPU | Original collision triangles in Z-up USDZ, supported cases, sealed native recipe |
| Train | One Nebius RTX PRO 6000 | Isaac GPU physics, native PPO updates, `policy.pt`, `training.json` |
| Evaluate | One Nebius RTX PRO 6000 | Reloaded checkpoint, physical controls, measured held-out episodes and `evaluation.json` |

Generation and training are separate reusable operations. Reusing an existing
world does not call the World API again or require its key on GPU workers.
The trainer and evaluator are the existing
[shared-scene navigation implementation](shared-scene-navigation.md); Marble
adds an input adapter, not another trainer or infrastructure controller.

## Headless operation

Use the existing Linux Workbench operator setup. For a new world, expose
`WLT_API_KEY` through the environment or private NPA credentials and run:

```bash
npa workbench marble acquire \
  --source generate --model marble-1.1 \
  --prompt "Realistic warehouse with a broad flat central aisle, pallet racks and continuous concrete floor" \
  --run-id warehouse-world \
  --output-path s3://<owned-bucket>/worlds/warehouse-world/
```

An already acquired world, including the warehouse collection example, can be
used directly. API credits fund generation; Marble weights do not run on Nebius.

Supply `world_uri` without a trailing slash and an **operator-qualified immutable Isaac image digest**.
The image must preserve the supported bootstrap/interpreter contract and provide
Isaac Lab `3.0.0b2.post1`, Isaac Sim `6.0.1.0`, and RSL-RL `5.0.1`. The repository's
historical public Isaac release is quarantined, so this workflow deliberately
has no implicit image default. A syntactically valid digest is not qualification.

```bash
npa workbench health preflight --project <project-alias> --checks nebius,s3 --json
npa skypilot verify --cluster <exact-context> --output-format json
npa workbench workflow validate-spec workflows/testing/marble-navigation-rl.yaml
npa workbench workflow submit workflows/testing/marble-navigation-rl.yaml \
  --project <project-alias> --infra k8s/<exact-context> \
  --run-id marble-navigation-learning \
  --var bucket=<owned-bucket> \
  --var world_uri=s3://<owned-bucket>/worlds/warehouse-world \
  --var isaac_image=<qualified-image@sha256:digest> \
  --stage-src --runtime --max-wait-seconds 0 \
  --secret-env AWS_ACCESS_KEY_ID --secret-env AWS_SECRET_ACCESS_KEY \
  --isolated-config-dir /var/lib/npa/marble-navigation-sky
```

Isaac uses the standard run-scoped `ACCEPT_EULA` default and honors explicit
opt-out; optional telemetry stays off. Preserve the isolated operator state
for status, resume, and cleanup through Workbench.

The default experiment has 4,000 concurrent robots, 500 PPO iterations, and
4,000 held-out cases evaluated for 300 control steps. These are training
parameters, configurable with `--var num_envs=...`, `iterations=...`, and
`episode_steps=...`. The CPU adapter samples an eight-meter radius around the
world origin on a 0.4-meter grid (`sampling_radius_m`, default `8.0`); `seed`
defaults to `42`. It requires finite supported footprints, clearance, a connected
region, a five-meter free-space control, an obstacle-contact control, and a
separate supported peer parking position. It fails on unsuitable generated
geometry without adding a plane or substituting a stock warehouse.

## Evidence and control-plane contract

The preparation operation is available through:

- CLI: `npa workbench marble navigation-prepare`.
- SDK: `npa.sdk.workbench.marble.navigation_prepare(NavigationRequest(...))`.
- Catalog: `workbench.marble.navigation_prepare`.

All call the same implementation. SkyPilot remains the only job orchestrator;
the agent selects inputs, submits the declarative graph, inspects status and
artifacts, and decides what to do next. The adapter never provisions resources
or launches nested workers. Cross-stage data travels through sealed S3 bundles.

The prepared bundle contains `marble-source.json`, `marble-support.json`,
`scene.usdz`, and `recipe.json`. The USDZ embeds the world-manifest hash, collider
hash, and coordinate transform; the same scene travels with the trained policy
and evaluation. The original triangle count is preserved. Coordinates convert
from Marble Y-up to native Z-up as `[world.x, -world.z, world.y]` after the
provider's scale and ground offset.

Training and evaluation retain the native conditional publication protocol.
Read each stage's `completion.json` to locate its immutable attempt and inspect
the checksums. Training requires an actual checkpoint hash. Evaluation reloads
that checkpoint, repeats the native contact/isolation controls, and fails the
workflow if measured success is below the recipe's 80% threshold. Failure
evidence remains available; a publication record alone is not a passing score.

Training and evaluation goal locations, seeds, and complete reset cases are
disjoint. Both splits use the same generated world; this is not an unseen-site
or real-robot generalization test. Provider-estimated meters are not surveyed
site calibration. No manufacturing productivity or physical-robot safety claim
follows from a successful synthetic evaluation.

## Validation status

Preparation was exercised against the actual generated warehouse: 106,181
original triangles, 299 supported sampling positions, 4,000 training cases,
and 4,000 evaluation cases with separate goal locations. Geometry conversion,
USD source provenance, case separation, and workflow contracts have local tests.

**Native ANYmal GPU training and held-out evaluation for this Marble adapter
remain unverified.** The completed rover RGB/depth collection proves the earlier
sensor workflow; it is not evidence for PPO. Acceptance requires one run using
the qualified runtime, a real checkpoint, and independently inspected evaluation
artifacts. This is the necessary live validation gap for the new learning path.
