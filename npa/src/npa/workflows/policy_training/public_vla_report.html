What each visual shows
  • Pipeline: the executed stages, from public LeRobot data through real gradient updates and simulator testing.
  • Three robot views: the downloaded policy, corpus-updated policy and task-adapted policy on the same validation starting state. Select any recorded episode; videos are native simulator outputs, played at 20 simulation steps per second (one quarter of their native encoded rate).
  • Training curves: recorded optimizer loss, averaged in consecutive windows for readability. The action expert and state projection train while the pretrained vision/language backbone stays frozen. Lower loss alone does not establish better task success.
  • Final test: the checkpoint selected using validation is evaluated on a separate range of fixed simulator starting states.
  • Checkpoint identity: a hash of actual trained weight bytes, with optimizer, scheduler, RNG and sampling state retained in the private run artifacts.
  • Runtime: the measured GPU and model size. This reference uses one GPU. The launcher supports a Kubernetes Job or a Slurm/Pyxis allocation; torchrun launches the training process inside it.
